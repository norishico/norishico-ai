# AYOkeiba / MC123 / mc_dyn 作業ルール

## ⚠️ MC123とmc_dyn(churn)は役割が違う。混同・統合しないこと

2つの独立したシミュレーターが存在する。**どちらも情報提供用で、買い条件には接続されていない**(v6.6のスコアリング・買い条件とは無関係)。

| | MC123 | mc_dyn(展開予想・churn) |
|---|---|---|
| 入力 | 各馬の**実力**(過去成績ベースのスコア) | 各馬の**脚質分類のみ**(classify_style_c2)。能力値はN(80,3)の**乱数**(predict_race_formation.py 206-208行) |
| 目的 | 「誰が勝つか」(p1/p2/p3/ptop3) | 「脚質構成×コース形状だけで展開・順位変動がどう起きるか」(隊列予測・churn_avg/label) |
| 出力先 | `mc_keiba_public/mc123_data.json` | `mc_keiba_public/pace_data.json` |

**能力値を乱数にしているのは設計ミスではなく意図的な役割分担**(2026-08-26確認)。もし実力をmc_dyn側にも混ぜると「展開が理由で入れ替わったのか、単に強い馬が来ただけなのか」の区別がつかなくなり、MC123の劣化コピーになる。実際にMC123(実力入り)でも下記の通り市場を超えられなかったため、実力を混ぜても新しいエッジが生まれる見込みは薄い。**「churnに実力を追加できないか」という改善案が出たら、まずこの設計意図を思い出すこと**。

## 🚨 レースの「荒れ/堅い」予測は市場超えの価値なし(2026-08-26検証済み)

5年・9,454レースの実データで検証済み(検証スクリプトはスクラッチパッド、`mc123_bt_results_v2.json`が既存の過去計算結果)。

- 「荒れる/堅い」自体はオッズ+出走頭数だけでかなり正確に予測できる(AUC 0.65-0.71)
- MC123を使っても**市場+頭数で説明できる範囲を一切超えない**(合成AUCが単独市場+頭数と同水準、上乗せゼロ)
- 当初「MC123の方が精度が良い」ように見えた箇所は**出走頭数との交絡**だった(頭数が多いレースほど荒れやすく、MC123もそれをなぞっていただけ)
- churn指標は能力ブラインドなので荒れ予測にはそもそも不向き(上記の役割分担理由)

→ 「荒れ度」は**情報表示(荒れ度メーター等)としては筋が良いが、馬券戦略・ROI改善には使えない**。プロジェクト全体で7系統のアプローチが到達した「現行データに市場超えの情報なし」という結論と整合する追加確認。

## その他の技術メモ
- `predict_race_formation.py`は当該レースの実測pos4等を一切使わない(循環参照防止、脚質入力はclassify_style_c2の凍結モデル)
- `pace_data.json`はgit管理外・毎日上書きのため過去分の履歴保存なし。churnの歴史検証をするなら再シミュレーションが必要(コストに見合わないため非推奨)
