# AYOkeiba / MC123 / mc_dyn 作業ルール

## ⚠️ MC123とmc_dyn(churn)は役割が違う。混同・統合しないこと

2つの独立したシミュレーターが存在する。**どちらも情報提供用で、買い条件には接続されていない**(v6.6のスコアリング・買い条件とは無関係)。

| | MC123 | mc_dyn(展開予想・churn) |
|---|---|---|
| 入力 | 各馬の**実力**(過去成績ベースのスコア) | 各馬の**脚質分類のみ**(classify_style_c2)。能力値はN(80,3)の**乱数**(predict_race_formation.py 206-208行) |
| 目的 | 「誰が勝つか」(p1/p2/p3/ptop3) | 「脚質構成×コース形状だけで展開・順位変動がどう起きるか」(隊列予測・churn_avg/label) |
| 出力先 | `mc_keiba_public/mc123_data.json` | `mc_keiba_public/pace_data.json` |

**能力値を乱数にしているのは設計ミスではなく意図的な役割分担**(2026-08-26確認)。もし実力をmc_dyn側にも混ぜると「展開が理由で入れ替わったのか、単に強い馬が来ただけなのか」の区別がつかなくなり、MC123の劣化コピーになる。実際にMC123(実力入り)でも下記の通り市場を超えられなかったため、実力を混ぜても新しいエッジが生まれる見込みは薄い。**「churnに実力を追加できないか」という改善案が出たら、まずこの設計意図を思い出すこと**。

## 🚨 レースの「荒れ/堅い」予測は市場超えの価値なし(2026-08-26検証済み)

5年・9,454レースの実データで検証済み(検証スクリプトはスクラッチパッド、`mc123_bt_results_v2.json`が既存の過去計算結果)。

- 「荒れる/堅い」自体はオッズ+出走頭数だけでかなり正確に予測できる(AUC 0.65-0.71)
- MC123を使っても**市場+頭数で説明できる範囲を一切超えない**(合成AUCが単独市場+頭数と同水準、上乗せゼロ)
- 当初「MC123の方が精度が良い」ように見えた箇所は**出走頭数との交絡**だった(頭数が多いレースほど荒れやすく、MC123もそれをなぞっていただけ)
- churn指標は能力ブラインドなので荒れ予測にはそもそも不向き(上記の役割分担理由)

→ 「荒れ度」は**情報表示(荒れ度メーター等)としては筋が良いが、馬券戦略・ROI改善には使えない**。プロジェクト全体で7系統のアプローチが到達した「現行データに市場超えの情報なし」という結論と整合する追加確認。

## 🚨 「会場×距離で1着の当てやすさが違う」は検証済みで不採用(2026-09-20検証済み、⚠️後述の訂正あり)

MC123のtop1予想馬(ptop3最大)について「複勝は当たるが1着は当たらないコースがある」という素朴な観察から、プランナー設計→ワーカー実行のT0〜T9調査(事後予測チェック・オフセット回帰・較正曲線・特徴量カバレッジ・ペース分布・MCノイズ・本番スコープ再現)を実施済み。詳細はメモリ`project_ayokeiba_mc123.md`参照。

- **会場×距離のセル差は2021-2023年限定の現象で、2024年以降・本番スコープでは統計的に検出不可**(事後予測チェックp=0.45〜0.79、BH-FDR補正後の有意セル0件)。この仮説を再検証する価値はない
- 生のセル別勝率・複勝率を頭数やクラスと直接比較しない。モデルは既に頭数等を織り込んでいるため、必ず「観測−予測(p1/ptop3)」の残差で比較すること(生の率で見ると交絡する)
- 「コースごとにBASE_NOISE_STD(ノイズ幅)を変えるべき」「特徴量が薄いコースが弱い」は探索したが不支持

### ⚠️訂正(2026-09-20、同日中に判明): 「先行馬の選定バイアス」は誤り。組成効果であり誤較正ではない

上記調査直後に「top1の47.9%が先行(実際の勝ち馬比率33.2%より過大)」を"本物の構造的バイアス"と記録したが、後続の実装設計フェーズでの脚質別**全馬**較正診断(top1に絞らない)により誤りと判明。**先行はむしろ最も較正が良い脚質**(実勝率/予測p1=0.973、逃げ1.160・追込0.924より1に近い)で、モデル自身が含意する脚質別勝率シェア(Σp1: 先行34.3%/差し44.6%/追込11.7%/逃げ6.6%)も実際の勝ち馬シェア(33.2/42.4/10.7/7.6)とほぼ一致している。top1(argmax)シェアが先行に偏るのは「複数脚質中で平均能力が最も高い脚質(先行の平均勝率9.6% vs 差し7.0%)がargmaxで選ばれやすい」という、正しく較正されたモデルでも起きる数学的性質であり、モデルの欠陥ではない。**「MC123は先行を選びすぎている」という主張は再度使わないこと**。

**実在する脚質関連の誤較正**(較正比=実勝率/予測p1、2023-25年):
- 距離依存: 短距離(ダ1200/芝1200)で逃げ過小(1.22〜1.36)・追込過大(0.66〜0.76)、芝2400m以上で先行過大(0.76〜0.83)・追込過小(1.19)
- 重・不良馬場での先行過大(0.87、`mc123_engine.py`の重馬場ボーナス0.6が強すぎる可能性)
- 逃げの全体的な過小評価(1.16)
- **低情報馬(履歴3走未満、classify_styleの騎手フォールバック="中団"ラベル)が2.0倍過小評価**(出走の3.6%、未勝利除外母集団では少走馬=早期勝ち上がり組で実際は平均より強い)。①②より効果が大きい可能性がある新候補

素朴な「差し・追い込みへの対称ボーナス追加」(先行バイアス是正のつもりの実装)はプローブ検証でBrier悪化(+0.10%)、素朴な「経験的ペース事前分布への差し替え」もBrier大幅悪化(+0.3〜0.9%、短距離で「差し有利」を誤って強め合わせてしまう構造的な罠)。実装するなら脚質×距離較正項(5係数、事前登録・座標降下で較正)という形にすること。詳細設計はプランナーエージェント(agentId a485531060c4559df)の設計書参照。

**独立検証で確認済み(別ワーカーagentId ae809e5d86ed46515、プランナーのコード非参照でゼロから再計算)**: 較正比・シェアの数値はプランナー報告と丸め誤差程度で完全一致。トイシミュレーション(較正誤差ゼロの合成データ)でも「argmaxは平均能力が高いグループを過大代表する」という同じ方向・同程度の乖離を再現し、組成効果である根拠を確認。**追加発見**: 逃げについては組成効果と逆方向に動いており(逃げは4脚質中最も実勝率が高いのに、top1シェアは勝ち馬シェアより低い)、別の理由と判明——逃げは「勝つか大きく崩れるか」の両極端になりやすく((p2+p3)/p1比が逃げ1.61<先行1.80<差し2.09<追込2.37と最小)、top1の定義に使うptop3(1-3着内確率)という指標が脚質ごとの結果分散の違いをそのまま反映しているだけ(これもバグではない)。**元のT0-T9報告にあった改善提案「先行を優遇するボーナス項の設計見直し」は取り下げ**。のりお承認済みで①(距離×脚質較正項、Track A/B判定)③(低情報馬K_LOWINFO)は実装ワーカーが較正・採否判定を完了(2026-09-20)。①はTrack A・Track Bとも事前登録基準未達で不採用(係数はコードに残置・値は現行のまま)。③は実装前診断で当初条件(n_runs_cta==0 OR 有効過去走<2)がベテラン馬を12.5%誤混入させることが判明したため「有効過去走<2」単独に絞り込んだ上でTrack Bを大幅にクリアし採用(K_LOWINFO=3.0、mc123_bt_results_v2.json再生成済み、次回水曜tier再計算で反映)。詳細は`mc123_engine.py`のK_NIGE_LEVEL等・K_LOWINFO直上のコメント、スクラッチパッドのstyle_terms_calibration_result.json/lowinfo_calibration_result.json/lowinfo_diagnosis.json参照。

## その他の技術メモ
- `predict_race_formation.py`は当該レースの実測pos4等を一切使わない(循環参照防止、脚質入力はclassify_style_c2の凍結モデル)
- `pace_data.json`はgit管理外・毎日上書きのため過去分の履歴保存なし。churnの歴史検証をするなら再シミュレーションが必要(コストに見合わないため非推奨)
- `analyze_mc123_top1_conditions.py`の障害レース除外は`'障害' in race_name`だけでは不十分(JV-Link由来のレース名切り詰めで漏れる)。距離ベースのJUMP_DISTANCES併用が必須(2026-09-20修正済み)
- `track_cond`はDB主流が1文字(良/稍/重/不)。JV-Link等一部データのみ2文字(不良/稍重)。エンジン判定は必ず`mc123_engine.normalize_track_cond()`経由にすること(2026-09-20、"不"判定漏れバグ修正)
